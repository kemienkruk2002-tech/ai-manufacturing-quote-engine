﻿MODEL DANYCH I BAZA MVP – W07044 / 92687521_A


Cel dokumentu


To jest specyfikacja pierwszej implementacji bazy danych dla AI Manufacturing Quote Engine. Nie budujemy jeszcze automatycznego ofertowania z poczty ani autonomicznego AI. Najpierw system ma poprawnie zapisać, odtworzyć i przeliczyć jeden rzeczywisty przypadek W07044 / Tuleja 92687521_A. Ten przypadek jest GOLDEN CASE i będzie regression testem dla kolejnych wersji.


ZASADA NR 1 – DETERMINIZM


Dla tego samego snapshotu wejścia, tej samej wersji reguł, stawek i polityki cenowej wynik kalkulacji musi być identyczny 100/100 razy.


AI nie zapisuje finalnego kosztu ani ceny. AI w przyszłości może zaproponować fakty, routing lub klasyfikację. Po zatwierdzeniu dane trafiają do ustrukturyzowanego snapshotu, a wszystkie obliczenia wykonuje kod deterministyczny.


1. ZAKRES MVP


W MVP zapisujemy i obsługujemy:
- detal / part,
- rewizję / wariant / wersję procesu,
- ilość ofertową,
- materiał,
- półfabrykat i normatyw materiału,
- maszyny i zasoby,
- routing technologiczny,
- Tj i Tpz,
- wymagania kontrolne,
- stawki kosztowe,
- snapshot kalkulacji,
- breakdown kosztu,
- politykę cenową,
- finalną ofertę jako wersjonowany draft,
- golden expected values do testów.


Poza zakresem tej fazy: poczta, automatyczne wysyłanie ofert, ERP, pełny parser wszystkich rysunków, ML uczący się na żywo, autonomiczne zatwierdzanie technologii.

Nie mieszamy pojęć:

21. STATUSY I BLOKADY


BLOCKED jeśli:
- brak ilości,
- quantity <= 0,
- brak zatwierdzonego routingu,
- operacja nie ma zasobu,
- brak wymaganej stawki kosztowej,
- brak materiału dla detalu wymagającego materiału,
- brak normatywu/półfabrykatu w wersji MVP,
- konflikt danych nie został zatwierdzony.


Nie używamy magicznych wartości typu 0, -1, 'UNKNOWN' w polach liczbowych.

23. HASHOWANIE I POWTARZALNOŚĆ


snapshot_hash = SHA-256 z kanonicznego JSON po normalizacji:
- stabilna kolejność pól,
- stabilna kolejność tablic routingu wg sequence_no,
- jawne jednostki,
- kwoty jako string decimal w ustalonej skali,
- daty ISO-8601,
- brak pól runtime typu createdAt w payloadzie obliczeniowym.


calculation_hash = SHA-256(snapshot_hash + wersje wszystkich silników).


Jeśli calculation_hash jest taki sam, wynik Cost Engine i Pricing Engine musi być identyczny bit-for-bit w reprezentacji kanonicznej.

26. DEFINITION OF DONE TEJ FAZY


Faza jest skończona dopiero kiedy:
- W07044 jest zapisany w bazie bez ręcznych wyjątków w kodzie,
- routing jest odtworzony z tabel,
- Time Engine przechodzi golden test,
- Stock Engine rozróżnia 3.540 kg od 5.298 kg,
- brak stawki blokuje kalkulację zamiast dawać zero,
- snapshot jest immutable,
- calculation_hash jest stabilny,
- 100 identycznych uruchomień daje identyczny wynik,
- zmiana jednego wejścia tworzy nowy snapshot/hash,
- stara kalkulacja jest możliwa do replay z historycznymi danymi,
- wszystkie krytyczne testy przechodzą w CI.


27. CO ROBI KAMIL / CHATGPT / CODEX


Kamil:

- analizuje kolejne źródła,
- przygotowuje precyzyjne zadania/prompt dla Codexa,
- weryfikuje, czy implementacja nie przenosi logiki kosztowej do AI.


Codex:
- implementuje modele, migracje, silniki, testy, API i UI debugowe,
- nie zmienia reguł biznesowych bez decyzji,
- każdy task kończy testami,
- nie używa LLM do funkcji, które są deterministyczne.
